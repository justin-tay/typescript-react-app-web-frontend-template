# 8.3 Architecture Patterns

<!-- arc42-generated -->

| Pattern                                 | Where                                                                                    | Notes                                                                                                                                                                                                        |
| --------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Layered, feature-sliced modules         | `src/app`, `src/features`, `src/shared`                                                  | Imports only downward; features are isolated from each other. A feature that needs something from another is composed by `app` (for example the overview's attention card is passed in as a slot). ADR 0002. |
| Gate and guard components               | `AuthGate`, `RequireAdmin`                                                               | The gate shows the sign-in card in place; the guard explains missing roles instead of letting every request fail with a 403.                                                                                 |
| One shell, thin layouts                 | `AppShell`, `Layout`, `AdminLayout`                                                      | Layouts supply navigation items, breadcrumbs and widths; ADR 0006.                                                                                                                                           |
| Hooks per data shape                    | `useResource` (one thing), `usePagedList` (a server-paged list), `useMutation` (a write) | Each returns discriminated states (`loading`, `loaded`, `error`) so pages cannot read data that is not there. `fetcher` arguments must be stable references.                                                 |
| Server-driven tables                    | `DataTable` plus `usePagedList`                                                          | Paging, sorting, search and filters are sent to the server; the table renders. Selection survives paging and is cleared when what the list shows changes.                                                    |
| State derived during render             | `AppShell`, `useResource`, `ReviewItemsTable`                                            | Adjusting state when a prop or other state changes, as React recommends, instead of effects.                                                                                                                 |
| Slots for cross-feature composition     | `AdminDashboard attention={...}`                                                         | Keeps the feature-to-feature rule intact.                                                                                                                                                                    |
| Single error mapping                    | `api-errors.ts`, `LoadError`, `ServiceUnavailable`, `ErrorBoundary`                      | One vocabulary: unavailable, failed, forbidden, validation, re-authentication required.                                                                                                                      |
| Cross-tab coordination without a leader | `BroadcastChannel` in `shared/session`                                                   | Every tab keeps its own countdown to the same deadline; no leader election.                                                                                                                                  |
